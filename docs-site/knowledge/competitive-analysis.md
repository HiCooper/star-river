# 支付服务商市场调研与借鉴分析

本文档调研市面主流支付服务商的管理后台能力，分析星河支付可借鉴的功能，按优先级排序。

## 市场现有服务商

### 第一梯队：官方平台

#### 支付宝 ISV 服务商后台

| 入口 | `p.alipay.com` 或 `open.alipay.com` |
|------|------|
| 定位 | 为 ISV 提供代商户接入支付宝的能力 |

| 模块 | 功能 |
|------|------|
| 商户进件 | 扫码授权绑定、小程序授权、分账能力勾选、token 管理 |
| 分账管理 | 记账本签约、多方分润规则、资金全程在支付宝体系内流转 |
| 商户管理 | 费率设置、能力授予、结算记录查询、风控监控 |
| 技术对接 | API 权限配置、回调 URL 管理 |

#### 微信支付服务商平台

| 入口 | `pay.weixin.qq.com` |
|------|------|
| 定位 | 为服务商提供代商户接入微信支付的能力 |

| 模块 | 功能 |
|------|------|
| 商户进件 | API 批量进件、资质审核、特约商户管理 |
| 产品中心 | H5 / APP / Native / 小程序支付开通，分账，数字人民币 |
| 交易管理 | 订单查询、退款处理、多维筛选、导出 |
| 对账 | 交易账单下载、自动对账、财务系统对接 |
| 营销工具 | 点金计划、支付即服务、支付后领券 |
| 数据分析 | 销售报表、自定义报表、导出 Excel/PDF |
| 账户中心 | 资金账户、提现设置、员工权限（分级管理） |
| 风控 | 异常交易监控、IP 白名单、限额设置、实时通知 |

### 第二梯队：聚合支付 SaaS

| 平台 | 定位 | 核心特色 |
|------|------|---------|
| **Ping++** | 纯 SaaS 聚合支付网关 | 多级商户体系（最多 6 级）、分润模板引擎、大数据 BI（阿里云 MaxCompute）、22 种 Webhook 事件、5 种角色权限 |
| **收钱吧** | 线下收单 SaaS | 门店/多级账户管理、扫码点单、集团账户资金归集、智慧门店 |

## 星河支付能力对标

### P0 — 已有基础（当前管理后台已实现）

| 能力 | 星河支付现状 | 对标参考 |
|------|------------|---------|
| 支付订单查询 | `/admin/orders` — 列表 + 详情 + 事件时间线 | 微信支付 + Ping++ |
| 应用/子商户管理 | `/admin/apps` — 创建/编辑 + 支付宝PID/微信子商户号字段 | 支付宝 ISV + 微信服务商 |
| 事件审计追踪 | `payment_events` 表 — created / channel_request / callback_received / status_changed / webhook_sent | 独有优势 |
| 渠道配置状态 | `/admin/config` — ISV/服务商凭证脱敏展示 | — |
| 数据仪表盘 | `/admin/dashboard` — 今日订单/收入/成功率/渠道分布 | Ping++ |

### P1 — 近期应补齐

| 能力 | 重要性 | 参考来源 |
|------|--------|---------|
| 交易筛选与 CSV 导出 | 微信和 Ping++ 均支持按时间/状态/渠道筛选 + 导出，是运营刚需 | 微信支付 / Ping++ |
| 子商户进件引导流程 | 支付宝 ISV 的核心入口，减少人工对接成本 | 支付宝 ISV |
| 对账报表（日报/月报） | 微信支付列为支付完成后的关键步骤，Ping++ 提供每日/每月报表下载 | 微信支付 / Ping++ |
| API Key 复制与重新生成 | 安全基础功能 | Ping++ |

### P2 — 中期差异化

| 能力 | 说明 |
|------|------|
| 成功率监控 + 告警 | 按渠道/应用统计成功率，低于阈值推送通知 |
| AI 对账助手 | 自动匹配差异订单，给出根因分析——契合「AI 时代」定位 |
| 多角色权限 | 超管 / 财务 / 技术 / 只读，按页面控制 |
| Webhook 投递仪表盘 | 展示 webhook 投递成功率、失败队列、手动重发 |

### P3 — 长期壁垒

| 能力 | 说明 |
|------|------|
| 智能路由 | 渠道故障时自动切换备用渠道（adapter 架构已预留） |
| 客户自助入驻 | 类似 Stripe Connect，子商户自助填资料 → 自动进件 |
| 自然语言查订单 | LLM 将自然语言转为 SQL 查询，降低运营门槛 |

## 总结

星河支付当前 P0 已覆盖服务商后台的核心模块。相比市场竞品，我们的差异化在于：

1. **事件审计链** — 每笔支付从创建到回调的完整事件时间线，Ping++ 和微信后台都没有做到这个粒度
2. **渠道无关的统一网关** — 支付宝和微信通过同一个 adapter 接口接入，切换渠道只需改参数
3. **AI 时代定位** — 管理后台只是起点，后续的智能对账、自然语言查询才是壁垒

下一步重点：打磨 P0 的交互细节，补齐 P1 的筛选导出和对账报表。
