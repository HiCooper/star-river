# 漏斗分析

漏斗分析帮助产品团队追踪用户在付费流程中的每一步转化，识别流失节点，优化付费墙和支付流程设计。

## 功能概述

漏斗分析支持自定义转化路径，按用户行为阶段拆解转化率，支持不同维度（渠道、设备、地区、用户群体）的横向对比。

## 漏斗阶段

### 标准付费漏斗

```
曝光 → 点击「订阅」 → 进入支付页 → 选择支付方式 → 确认支付 → 支付成功
```

每个阶段的转化率计算公式：

$$
转化率_n = \frac{下一阶段用户数}{本阶段用户数} \times 100\%
$$

### 关键漏斗

| 漏斗名称 | 适用场景 |
|---------|---------|
| 付费转化漏斗 | 日常监控付费转化健康度 |
| 新用户订阅漏斗 | 分析新用户首次付费路径 |
| 流失挽回漏斗 | 分析退订用户再次付费路径 |

## 漏斗构建

### 1. 选择事件

从预设事件或自定义事件中选择漏斗各阶段对应的事件：

| 事件 | 说明 |
|------|------|
| `paywall_view` | 付费墙展示 |
| `paywall_click` | 点击订阅按钮 |
| `checkout_start` | 进入结算页 |
| `payment_method_selected` | 选择支付方式 |
| `payment_confirm` | 确认支付 |
| `payment_success` | 支付成功 |

### 2. 设置时间窗口

- **序列窗口**: 各阶段之间的最大时间间隔（如 24 小时内完成）
- **回溯窗口**: 从第一个事件开始向前/向后延伸的时间范围

### 3. 添加筛选条件

支持按以下维度筛选：
- 平台（iOS / Android / Web）
- 地区
- 用户群体（首次付费 / 复购 / 流失用户）
- A/B 实验组

## 分析视图

### 漏斗图

```
┌─────────┐
│ 曝光    │  10,000 (100%)
│ 10,000  │
└────┬────┘
     │ 35%
     ▼
┌─────────┐
│ 点击    │  3,500 (35%)
│ 订阅    │
└────┬────┘
     │ 60%
     ▼
┌─────────┐
│ 进入    │  2,100 (21%)
│ 结算页  │
└────┬────┘
     │ 80%
     ▼
┌─────────┐
│ 确认    │  1,680 (16.8%)
│ 支付    │
└────┬────┘
     │ 95%
     ▼
┌─────────┐
│ 支付    │  1,596 (15.96%)
│ 成功    │
└─────────┘
```

图中标注：
- 每阶段的绝对人数
- 该阶段相对第一阶段的整体转化率
- 两个阶段之间的步进转化率

### 对比分析

支持多维度横向对比：
- **实验组对比**: 同一漏斗在不同 A/B 实验组中的转化率
- **时间对比**: 同一漏斗在不同时间段的对比
- **渠道对比**: 同一漏斗在不同平台/渠道的对比

### 流失分析

识别流失最大的节点：
- 高流失节点标红提醒
- 提供该节点用户的特征画像
- 支持下钻查看流失用户的具体行为序列

## 漏斗优化建议

系统根据漏斗数据提供优化建议：

| 流失节点 | 建议策略 |
|---------|---------|
| 点击→结算页流失高 | 优化按钮文案或位置 |
| 结算页→支付方式流失高 | 简化支付流程，增加信任标识 |
| 支付确认→成功流失高 | 检查支付渠道稳定性 |

## 导出与分享

- **导出**: 支持导出为 PDF 报告或 CSV 数据
- **分享**: 生成公开链接，其他成员可查看（只读）
- **订阅**: 设置定时推送，将漏斗数据定期发送到邮箱

## 常见问题

**Q: 漏斗数据有延迟吗？**
A: 事件数据约有 5-10 分钟延迟，支付成功数据可能有 1-2 分钟延迟。

**Q: 可以分析自定义事件吗？**
A: 可以，只需在 SDK 中上报自定义事件，即可在漏斗中使用。
